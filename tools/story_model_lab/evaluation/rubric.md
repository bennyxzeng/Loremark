# 人工评审口径

自动校验只说明输出结构合法、ID 引用正确、引用原文逐字存在。它不说明引用支持结论，也不说明信息完整。本口径用于人工判断内容质量。

评审只依据被选章节的原文（`chapter.txt` 或 `review.md` 附录）。不要用对这部小说其他章节、其他卷或改编作品的了解来判对错；那类知识本身就是要检查的“章外内容”。

## 1. 抽查生成主张

一条“主张”是一条可单独判断的记录：一个属性、一个别名、一条关系、一个事件，或一个疑点。

- 至少抽查 10 条；不足 10 条则全部检查，并写明总数。
- 覆盖人物/属性、关系、事件三类。
- 覆盖章节开头、中间、结尾（按证据段落在本章中的位置三等分）。
- 写明选样办法（例如：每类按出现顺序取第 1、中间、最后一条），不要只挑看起来好的。

每条给出一个结论：

| 结论 | 含义 |
| --- | --- |
| `supported` | 原文支持该主张，assertion 和时间标签也恰当 |
| `contradicted` | 与原文矛盾（包括关系方向反了、把角色说法当成事实且原文明示其为假） |
| `unsupported` | 原文不足以支持；引用存在但说的是别的事，或推断过度 |
| `needs_review` | 评审者无法确定，需要第二人看 |

另外按需标记（可多选）：

| 标记 | 含义 |
| --- | --- |
| `identity_confusion` | 把两个实体合并，或把一个实体拆开，或别名链接无本章依据 |
| `time_confusion` | 倒叙当作当前事件，计划当作已发生，或反之 |
| `relation_direction` | source/target 方向错 |
| `over_inference` | `inferred` 超出本章文本能支持的范围，或 `explicit` 实际是推断 |
| `omission` | 记录本身遗漏关键限定（例如漏掉“据称”） |
| `outside_chapter_knowledge` | 内容疑似来自本章之外（后续情节、作品常识） |

assertion 的判断：`reported` 只表示“有人这么说”，不要求说法为真；如果模型把角色或广播的说法标成 `explicit`，算 `unsupported` 并加 `over_inference`。

## 2. 预期重要信息点覆盖

在查看模型输出**之前**，独立阅读原文选出至少 10 个重要信息点（主要情节推进、关键人物行为、重要揭示、关键身份/关系），每点记录段落 ID 和简短原文。然后检查输出是否覆盖：

| 覆盖 | 含义 |
| --- | --- |
| `yes` | 有记录明确表达该信息，且结论为 supported |
| `partial` | 只覆盖一部分，或表达不准确 |
| `no` | 没有对应记录 |

不能把模型输出反过来当标准答案，也不要在看过输出后修改信息点清单；如需增补，单独列出并注明是事后增补。

## 3. 可以报告的数字

- 抽查支持率 = `supported` 数 / 已抽查主张数。同时给出分子、分母和 `needs_review` 数。
- 所选重要信息点覆盖率 = `yes` 数 / 所选信息点数；`partial` 单独列出。

不要把它们称为全书准确率、完整 recall 或模型准确率；不要把 schema 通过率或引用匹配率说成事实准确率。没有对全章做完整标注，就不报告全章 recall。

## 4. 记录方式

复制 `review_template.json` 填写，长原文和模型输出留在 gitignored 的 `runs/` 中；评审文档只写必要的短引用和段落 ID。结论与改进建议写进 `sample_review.md` 或新的评审文档，注明运行 ID、provider、模型、prompt/schema 哈希。
